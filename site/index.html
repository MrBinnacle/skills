Less prompting. Better plumbing.

The agent says “Done.” It never ran the tests. The check passed. It could not have failed. The deploy went out. The page still serves the old build.

Each of these happened in real work with a coding agent. This repository is what got built in response.

  • Guards are code that runs on the agent’s action, so nothing depends on the agent remembering an instruction. Runs in Pi.
  • Cards are instructions an agent loads for one specific mistake. Runs in Claude Code and Pi.
  • Mods add to Claude Code’s own interface. Runs in Claude Code.

Install in Claude Code

Run these one at a time. Claude Code reads a paste of both as one malformed URL.

/plugin marketplace add https://github.com/MrBinnacle/skills.git /plugin install mrbinnacle-engineering

Install mrbinnacle-orchestration, mrbinnacle-meta, binnacle-hud and tips-anywhere the same way if you want them. They appear after /reload-plugins.

Install in Pi

Use the install command in the README.

See a guard fire

With Pi installed, clone the repository and run the demo from its root. It needs no API key and takes a few seconds.

git clone https://github.com/MrBinnacle/skills.git cd skills node mechanisms/verify-gate/demo.mjs

An agent is asked for a 10% discount and writes a bug. In the first run it says “Done.” and the bug ships. In the second run the guard sends it back to run the tests, and it reports the failure. The agent’s replies are scripted, so you see what the guard does and not what a model makes of it.

How it is kept

ADMISSION.md is the rule for which cards get in, and RETIRED.md lists the ones that left. The runtime delivery matrix records which installs were checked, on what, and when. The changelog says what each version changed.

Contribute

If your agent keeps making a mistake that nothing here covers, open an issue and say what happened. Fixes and new guards are welcome as pull requests. Report a security problem through the private form, not a public issue.
