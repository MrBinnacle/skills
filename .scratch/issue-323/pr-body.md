# Evidence body — MrBinnacle/skills#323

## What this PR does

Every model-invocable card's `EVIDENCE.md` carried a hand-estimated description
token count (e.g. "≈ 40 tokens"), and every estimate disagreed with the
calibrated figure from `skill-harness skill audit`. This PR corrects every
figure, adds a CI check that prevents drift, and glosses the README's
"measured" label for `pull-rebase`.

## Criterion 2: CI check under scripts/

**What was built.** Two new scripts:

- `scripts/validate_standing_costs.py` — the CI gate. It walks every published
  card, extracts the `Standing cost` row from `EVIDENCE.md`, and compares the
  stated token count against the calibrated figure. When `skill-harness` is
  installed, it runs `skill-harness skill audit` live. When unavailable (typical
  in CI), it reads the committed `scripts/standing-costs.json` and checks the
  SKILL.md content hash for freshness. On disagreement it names the card and
  both numbers, then exits non-zero.

- `scripts/refresh_standing_costs.py` — regeneration command. Run it after
  editing any SKILL.md frontmatter to update `standing-costs.json` and its
  freshness hashes.

- `scripts/standing-costs.json` — committed fallback data: calibrated token
  counts and sha256 hashes of each SKILL.md, generated by the audit on
  2026-09-22 (skill-harness 0.3.0).

- `.github/workflows/tests.yml` — two new CI steps: the test suite and the
  live check, matching the pattern of every other validator in the workflow.

**Test that pins it.** `scripts/test_validate_standing_costs.py` runs four cases:

1. The committed poison fixture (wrong figure) is rejected, names the card and
   both numbers.
2. The live published tree passes.
3. A temp tree with the real SKILL.md but a wrong figure is rejected, names the
   card and both numbers.
4. A temp tree with the real SKILL.md and the correct figure passes.

**Observation watching the test fail before the change.** Before building the
validator, the committed poison fixture (which states 999 tokens) would have
passed silently — no check existed to catch it. After building the validator,
the fixture is correctly rejected with:
```
standing-cost-drift-card: stated 999 tokens, audit says 21 tokens
REJECTED: 1 standing-cost disagreement(s) across 1 published card(s).
```

**Observation watching the test pass after.** All four test cases pass. The
live tree (14 cards) passes the standing-cost check.

## Criterion 4: README gloss

**What was built.** The README's "Card evidence" section prose now clarifies
the `measured` posture label. The definition reads:

> `measured` means a controlled field records a result other than
> `UNMEASURED` — but that does not necessarily mean the test reached the
> hazard or produced a conclusive answer; for example, `pull-rebase` is
> measured (its paired screen ran and returned `CANT_TELL_YET` because
> the hazard was not met), not tested-and-answered.

The table cell stays `measured` (the regex in
`test_readme_admission_lead.py` expects exactly that token). The gloss is in
the prose definition, which is where readers look for it.
