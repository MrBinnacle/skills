The three Pi extensions move from `pi/extensions/` to a top-level `mechanisms/` directory beside the cards, with a `README.md` that names, per mechanism, the card it enforces and the event it fires on. The in-process reviewer enforces `disposition-schema`, `decision-rights` and the `reviewer-horizon` candidate; the session packet enforces `im-down` and `im-up`; the verification gate enforces a rule no published card states — a run that edited must run a check before it settles — and the README says so rather than borrowing `vacuous-check` or `mocked-stub`, which ask the next question, whether the check that ran could fail. `DESIGN.md` keeps its observed Pi 1.1.0 behaviour and live proofs as the version pin and drops one machine's absolute paths and session id. `pi/PORTING-BRIEF.md`, the prompt that translated Claude Code terms into Pi terms for the first twelve ports, is deleted: the AGENTS.md Harness neutrality rule replaced that approach with cards that name neither harness, and its translation table is not carried anywhere. A `.pi/engineering-env.json` at the repository root names this repository's checks for the gate — the python validators, suites and prose-claim checks, verify-mode `release_gate.py`, `bun test`, `pre-commit` — because the gate's defaults match none of them and the file replaces the defaults rather than merging. The move is outside every card validator's walk; `bun test mechanisms` runs 109 tests across 10 files.
