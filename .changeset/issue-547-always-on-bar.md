Four cards now run by hand instead of loading in every session: `clirunner-env`, `mocked-stub` and `stale-deploy` in `mrbinnacle-engineering`, and `decision-rights` in `mrbinnacle-orchestration`. Each sets `disable-model-invocation: true`, so on Claude Code its description no longer sits in your context and the model cannot invoke it on its own. The new rule, [ADR 0008](https://github.com/MrBinnacle/skills/blob/main/docs/adr/0008-always-on-needs-two-occasions-or-a-controlled-result.md), lets a card load in every session only when its evidence record counts two or more occasions or carries a controlled result. Each of the four counts one occasion and has no controlled result. `pull-rebase` counts one occasion too and stays, because its paired screen returned `CANT_TELL_YET`. A card that clears the bar later can return to every session, and that move is a minor change. `scripts/validate_card_files.py` now refuses a model-invocable card below the bar. The effect of `disable-model-invocation` on hosts other than Claude Code is unmeasured.

Action for installed users: after you update, the four cards no longer fire on their own; run one by name when its situation arises, as `/mrbinnacle-engineering:clirunner-env`, `/mrbinnacle-engineering:mocked-stub`, `/mrbinnacle-engineering:stale-deploy` or `/mrbinnacle-orchestration:decision-rights` (or `/<card>` for an `npx skills add` install), and if a hook or rule in your own setup tells the model to call one of them, back it with a guard on the tool call or a personal copy without `disable-model-invocation`, because Claude Code refuses the model's call.
