A repeatable acceptance run for the Pi harness, `pi/scripts/accept_pi.py`, beside the `rpc_drive.py` and `probe_pi.py` scripts it reuses. Six scenarios, each in a fresh scratch git repository and a fresh `pi --mode rpc --no-session` process with the user's real settings: a successful change with its check, a planted failing test with "do not change any existing test", an edit with no check requested, a scripted LF-to-CRLF conversion, an edit where the user forbids shell commands, and a network scenario (S6) that proves the two lookup capabilities the global AGENTS.md rule depends on: a web fetch through `pi-web-access` and a docs lookup through Pi's built-in MCP with context7, graded on the tool results (the page title and the library ids the tools actually returned) rather than on the model's text. Before any scenario runs it probes what Pi loaded and refuses to run against the wrong model or without the mechanisms' commands. Grading reads the RPC event stream (tool calls in order, verify-gate nudges as `entry_appended` custom messages, eol-guard notes in tool results) and the scratch repository afterwards (git diff, byte counts, a pytest run by the grader); the model's final text is graded against that, on whether the measured pytest summary is among the ones it quotes. Rows marked `(info)` are excluded from the tally; `--regrade DIR` re-applies the grader to a saved run with no model spend. Measured 2026-10-10 on the configured default model: two full runs 20/20, one S5 re-run 4/4, and, after the harness gained web access and the UI packages, one full six-scenario run 25/25; the gate nudged in 4 of 4 runs that tried to settle with an unchecked edit and in 0 of 6 where a check had run. The script is not a gate check command: it spends model calls.
