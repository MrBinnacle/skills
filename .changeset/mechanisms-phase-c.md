Two mechanism changes and four brand-kit word repairs. The verification gate now ignores an `edit` or `write` whose path lies outside the session's project root (`ctx.cwd`): measured 2026-10-10 over the first day, 7 of 8 nudges named files under the operator's handoff directory, outside every repository, where no project check applies. The gate also counts a check command run through the `powershell` tool the same as one through `bash`. A new `mechanisms/eol-guard/` extension compares each tracked file's line endings against HEAD after `write`, `edit`, `bash` or `powershell` and appends a note to the tool result the model reads next when a file went from LF-only to CRLF-only or the reverse — the uniform conversion a mixed-endings predicate cannot see, which the `uniform-eol` candidate's `guard-design.md` specifies. It is built on the installed Pi 1.1.0 `tool_result` API (`content` returned with `structuredContent`), reads one repository, the session's, and disables itself with a notice outside a git repository. `mechanisms/README.md` and `DESIGN.md` carry the new row. In `pi/skills/`, the Pi copies of `nameable-half` and `reviewer-horizon` replace two words `assets/tokens.json` lists under `copy.words_to_avoid` with plain words so `validate_brand_kit.py` passes; the `_quarantine/` sources are untouched. `bun test mechanisms` runs 119 tests across 11 files.
