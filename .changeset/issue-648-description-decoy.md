The card-file check reads a card's description more strictly in four places (#648). It refuses a frontmatter with more than one line that starts with `description:`. Before this change it measured the first such line, so a short decoy inside a multi-line `license:` value, or a duplicate key, let a 300-character description pass the 200-character bar. It refuses a frontmatter line that starts with none of `name:`, `description:` or `disable-model-invocation:`, the only keys AGENTS.md permits. Without this rule a decoy still passed when the real key was spelled `"description":` or `description :`; a blank, comment or indented line in the frontmatter now fails as well. It now reads a one-word value that starts with a digit, such as `3d-printing` or `1st`, as text, and refuses what YAML 1.1 or 1.2 reads as a number or date, plus a few strings shaped like one, such as `0X1F`. Before this change those values were refused with a message that the card states no description. It refuses a description that holds nothing but escapes and spaces, such as `"\0"` or `"  "`. Every published card already passes, so no card changes and an installed user loses nothing.
