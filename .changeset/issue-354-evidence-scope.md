Every published card's `EVIDENCE.md` gains an `| **Evidence scope** | ... |` row, and CI refuses a card whose row is missing or disagrees with what its linked receipt shows. This is a patch. ADR 0005 (`docs/adr/0005-the-install-route-is-what-a-consumer-resolves.md`) states the rule: "A change is major only when an installed user who takes no action loses something they had, or must act to keep it." An installed user loses nothing here. Every card keeps its name, its directory and its three files, so the on-disk file shape that ADR 0002 and ADR 0003 price as major does not change. The row is added content inside an existing file. The 3.1.0 release priced the same kind of change as a patch: `.changeset/gotchas-pointers.md` (#336) added a required line to every published `SKILL.md` and a validator refusal.

The row's value is derived from the receipt conformance O5 already resolves from the card's `Receipt:` clause under `--harness-root`, using the closed set from skills#353: `UNMEASURED — no receipt.`; `NOT DEMONSTRATED — receipt verdict <VERDICT>; no effect is shown.`; `UNSCOPED — the KEEP receipt carries no verdict_scope (SERS before 1.6.0).`; or, for a KEEP receipt with a `verdict_scope` object, skill-harness's own scope line (standard and carried-forward forms), filled field by field to equal `skill_harness/sitegen/render.py::_scope_line` with the HTML wrapper removed and without HTML escaping. When a card links more than one receipt and none is a usable KEEP, the NOT DEMONSTRATED row names every distinct verdict among the linked receipts, in receipt order, deduplicated — two receipts carrying the same verdict name it once — with the standard ending (for example `NOT DEMONSTRATED (CANT_TELL_YET, NO_LIFT); no effect is shown.`). When a card links a KEEP receipt together with any non-KEEP receipt, the row keeps the KEEP scope sentence and then names every other distinct linked verdict, in receipt order, deduplicated (for example `… Other linked receipts: NO_LIFT.`). A public row must not hide a linked verdict. Thirteen cards read the UNMEASURED sentence; `pull-rebase` reads the NOT DEMONSTRATED sentence against its CANT_TELL_YET receipt. Quarantine cards and `scripts/fixtures/` are exempt.

The card-files validator adds `Evidence scope` to its contract-row set. The conformance validator checks the value, including the no-receipt case O5 skipped by returning CANNOT-CHECK, and refuses an empty row with its own message. The scope-line templates are constants in `scripts/validate_conformance.py` with a comment naming `skill_harness/sitegen/render.py::_scope_line` as the source. A drift test imports that function from a skill-harness checkout (`SKILL_HARNESS_ROOT`), renders the R2 KEEP fixtures through it, and compares the unescaped text with this repository's derivation; it skips with a named reason when no checkout is set. `.github/workflows/tests.yml` checks out `MrBinnacle/skill-harness` at its default branch and runs that test on ubuntu-latest.
