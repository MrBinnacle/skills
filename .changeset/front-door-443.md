The README, the landing page and the social preview now describe Skills as a knowledge base and a set of skill cards for engineering work with frontier models, and link the knowledge base from the front door. They say that Pi is the runtime this work targets first and that there is no tested Pi install yet. The `npx skills add MrBinnacle/skills` line is gone from the README and the social preview, because no receipt shows what it installs from the current tree. The README install section now states, for Windows, the measured limit on the length of the Claude configuration directory path (`CLAUDE_CONFIG_DIR`), what `git config --global core.longpaths true` changes, and the conditions of that measurement (#452). No card changes in this entry. Two other changes in 3.1.0 ask some installed users to act. If you set a relative `receiver_check_cache` path for `im-down` or `im-up`, the cache now lives under `~/.cache/mrbinnacle-skills/`, so the first session after you update runs every check once (#396). If you built a guard from the `pretooluse-prose` detector code, copy it again (#405). If neither applies to you, you need do nothing.
