The banner line is retired and replaced. It read *"These aren't the Claude Code skills you're looking for."* at eleven places across six files; it now reads **"14 skill cards. Each states the condition that would retire it."**, and the sites that lead with the repository name read **"skills. 14 skill cards. Each states the condition that would retire it."**

The old line was a joke about a film. It said nothing a reader could check, and it survives the substitution test the S425 direction brief adopted: swap `skills` for any competitor's name and the sentence reads exactly as true, which means it was never about this collection. The new line states a fact and names the rule the collection runs on.

**The count is derived, not written down.** A count on a page is the thing owner rulings retired from this banner twice for rotting, most recently on 2026-08-23, and the new wording puts one back. So `scripts/validate_scoreboard.py` no longer holds the sentence as a constant. `RULED_LINE_TEMPLATE` holds the shape and `ruled_line(root)` fills the number from `count_admitted(root)` — the same derivation the records already use — on every run. Add a card or retire one and the sentence every site must carry changes with it, so a site left behind is a build failure rather than a stale graphic nobody re-reads. Verified by adding a fifteenth card to a scratch copy of the tree: the run reddens immediately and demands `15 skill cards`.

**The separator is a period, not an em dash.** Direction brief T4.9 admits no U+2014 in a new `aria-label`, text node, heading or body line, and §4.4 makes that binding on exactly this replacement. The approved wording carried an em dash, so the two were in conflict; the owner chose the period over a waiver on 2026-09-07. The `skill-harness` half of the same rename inherits the choice.

Sites changed, all eleven: `README.md` image alt; both banner SVGs, each in its `aria-label` and its rendered `<text>` node; `AGENTS.md`, where the ruled line is quoted; `site/index.html` in the description, `og:description` and `twitter:description` meta tags and the `<h1>`; and the template in `scripts/validate_scoreboard.py`.

Three records are deliberately unchanged, because rewriting them would make them false: `CHANGELOG.md`, which records what shipped under the wording in force at the time, and the two front-page design variants under `docs/design/variants/`.

**The three drift fixtures move with it, and each keeps its single planted defect.** `origin-tier-drift` and `verdict-vocabulary-drift` carry a correct banner at every site by design — their whole value is that the banner cannot be the reason they fail — so both now carry the derived line for a two-card tree. `banner-line-drift` keeps its one softened site, re-expressed against the new sentence: it planted *"These are not"* for *"These aren't"*, an expanded contraction, and now plants *"might retire it"* for *"would retire it"*, a hedged claim. All three still fail, still for their own reason, and each still matches the substring its CI control greps for.

**One repair the rewording forced, and it is the more useful half of this change.** Two non-vacuity checks in `scripts/test_validate_brand_kit.py` proved the SVG scanner reads real copy by asserting the literal `"Claude Code skills"` appeared in what it extracted. They went red on this change with the scanner untouched, because they were pinned to a wording rather than to a behaviour. They now read the banner's own last `<text>` element with an independent regex and assert the scanner returns it, so a future rewrite of the copy cannot break them. XML comments are stripped before that regex: the banner documents its own layout in a comment that names a `<text>` element, and the raw-file match captured that prose instead of the rendered line. Both checks were re-proven against a blinded scanner, which still turns them red.
