## Reproducing the receipts

On Windows, with a signed-in Claude Code login and the repository checked out:

```bash
python -I _quarantine/walk-the-recipe/replay/replay.py positive v3.0.1 README.md <out-dir>
python -I _quarantine/walk-the-recipe/replay/replay.py negative v3.1.0 README.md <out-dir>
```

The driver is [replay.py](replay/replay.py), a Python port of the `replay.sh` that produced the
committed receipts (sha256 `94bdaab0cc54dbc01c5e895705713bf26d4bc5f1862e0f7035de0e06d728771c`, removed because shell scripts are not a
declared readable format). The port keeps the empty agent environment and the copied login, and
deletes the login in a `finally` block even when the run is interrupted. It has not produced any
committed receipt. It marks a run invalid when no recipe step
executed. A model run is not byte-reproducible, so a rerun checks the classification, not the
hash; the hash checks that the committed trace is the one the run wrote. The committed
negative trace was written before two driver fixes (UTF-8 and LF transcript output, and running
`strip_system.py` inside the driver); both act after the agent exits, and the same filter was
applied by hand before hashing; both transcripts were normalised to LF the same way.
