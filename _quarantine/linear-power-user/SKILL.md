# Linear power user

Inspect before mutating. Read the current workspace and relevant objects, model the outcome and smallest useful structure, plan consequential changes, execute with validated references, read changes back, and report verified results and partial failures.

Read [object-model.md](object-model.md) before choosing an object type or tool parameters. Read [project-method.md](project-method.md) before diagnosing a project, choosing an intervention, view or monitoring, structuring work, or reporting. Read [gotchas.md](gotchas.md) when a write fails, a read is partial, or evidence is incomplete.

Do not invent IDs, statuses, labels, assignees, dates, or dependencies. Reuse existing objects and conventions. Preserve fields the request does not name. Do not delete, archive, bulk-reassign, or change broad configuration without explicit authorization. Missing evidence is not proof of absence, non-use, or completion. Stop dependent writes when a prerequisite fails. Do not claim success until the tool confirms it and a read-back verifies important fields and relationships.

For broad work, use DISCOVER → MODEL → PLAN → EXECUTE → VERIFY → REPORT. For small edits, keep this proportionate. Ask one targeted question when consequential ambiguity cannot be resolved from the workspace; otherwise execute.

Workspace facts change. Re-read live state rather than trusting any recorded snapshot of teams, statuses, labels or templates.
